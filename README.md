# Workflow‑PNCECS (مسار + البوابة الإدارية)

مشروع Flask/SQLAlchemy يجمع بين:
- **نظام مسار (Workflow Engine)** لإدارة الطلبات/المعاملات والموافقات والتنبيهات والتقارير.
- **البوابة الإدارية (Portal/HR)** لتقديم خدمات الموظف (دوام/حضور/مغادرات/إجازات/مستودع… حسب الصلاحيات).

> **ملاحظة:** هذا المستودع مخصص للتطوير الداخلي. تأكد من ضبط الإعدادات الأمنية قبل النشر.

---

## المتطلبات
- Python **3.11+** (يعمل على Windows وLinux)
- SQLite (افتراضيًا) — ويمكن التبديل لاحقًا إلى PostgreSQL

---

## تشغيل سريع (Development)

### 1) إنشاء بيئة وتشغيل المتطلبات
```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -r requirements.txt
```

### 2) تهيئة قاعدة البيانات + Seed
```bash
python init_db.py
```
سيقوم السكربت بإنشاء الجداول + الفهارس + Seed من ملف `seed.xlsx` (إن وجد) وإضافة مستخدمين افتراضيين.

### 3) تشغيل التطبيق
```bash
python app.py
# أو
flask --app app run --debug
```

يشغّل الأمر `python app.py` التطبيق افتراضيًا بوضع الإنتاج عبر Waitress على العنوان
المحلي `127.0.0.1:5000`. لتشغيل نسخة الشبكة على الخادم `10.10.10.204` استخدم:

```bash
python serve.py
```

يرتبط ملف `serve.py` افتراضيًا بعنوان الخادم `10.10.10.204` والمنفذ `5000`، ويصبح
رابط النظام:

```text
http://10.10.10.204:5000
```

يمكن تخصيص التشغيل عبر متغيرات البيئة التالية:

```text
APP_ENV=production
APP_HOST=10.10.10.204
APP_PORT=5000
APP_SERVER_THREADS=8
SECRET_KEY=ضع-هنا-قيمة-عشوائية-طويلة-وثابتة
```

للتطوير فقط، استخدم `APP_ENV=development`. يجب كذلك السماح بالمنفذ المختار في
جدار حماية الخادم، أو ربط Waitress بخادم Reverse Proxy على المنفذين 80/443.

## «اسأل عارف» داخل النظام

يظهر زر **اسأل عارف** للمستخدم المسجّل في مسار والبوابة الإدارية. يعمل افتراضيًا
كمساعد معرفة محلي، ولا يحفظ المحادثات في قاعدة البيانات. يجمع الإجابة من:

- بيانات الحساب والمعاملات والإشعارات والمراسلات ودليل الموظفين بعد تطبيق صلاحيات المستخدم والسرية.
- فهرس محلي للكود والقوالب وJavaScript وCSS والوثائق والسكربتات وقائمة ملفات المشروع.
- خريطة مسارات Flask الفعلية ومخطط SQLAlchemy/SQLite والعلاقات وأعداد السجلات.
- بيانات مرجعية آمنة من الجداول الإدارية، مع حجب قيم كلمات المرور والمفاتيح والرموز دائمًا.

لا يحتاج المستخدم إلى معرفة ماذا يكتب أو كيف يصوغ السؤال. تبدأ النافذة بقائمة
مساعدة موجّهة، ويمكن الرجوع إليها في أي وقت من زر القائمة أعلى النافذة. تشمل:

- **اشرح هذه الصفحة:** يوضح فائدة الشاشة الحالية وما يمكن فعله فيها.
- **أنجز مهمة:** خطوات جاهزة لإنشاء الطلبات ومعالجة المهام والإجازات والمراسلات والأرشيف وطلبات الصلاحيات.
- **خذني إلى شاشة:** روابط مباشرة إلى الشاشة المناسبة حسب صلاحيات الحساب.
- **ابحث واعرض بياناتي:** الطلبات والإشعارات والمراسلات والصلاحيات ودليل الموظفين والملخص اليومي.
- **حل مشكلة:** إرشاد للصفحات التي لا تفتح، والأزرار المفقودة، والطلبات المتوقفة، والمرفقات، والبيانات غير الظاهرة، وانتهاء الجلسة.
- **الأدلة الكاملة:** الوصول إلى مركز أدلة النظام. وتظهر للإدارة مساعدة إضافية للكود وهيكلية المشروع وقاعدة البيانات والصلاحيات.

يبقى مربع الكتابة متاحًا لمن يفضّل السؤال الحر، ويكفي وصف الحاجة بكلمات بسيطة
مثل: «لا أجد زر الاعتماد» أو «أين أجد إجازاتي؟».

### المحادثة الطبيعية مع عارف

يتعامل الوضع المحلي مع الكلام اليومي الشائع مثل التحية والشكر و«كيف حالك؟»،
ويرد بتفاعل مبسط ويتذكر الرسائل السابقة داخل جلسة المتصفح. أما المحادثة الحرة
المفتوحة في أي موضوع، وفهم العبارات العامية والمتابعة الطبيعية للسياق، فتحتاج إلى
تفعيل نموذج الذكاء الاصطناعي. عند تفعيله يرسل عارف آخر رسائل المحادثة مع كل طلب
ويطلب من النموذج متابعة الضمائر والأسئلة اللاحقة، مع إبقاء حقائق النظام محصورة في
المعلومات التي استرجعها عارف بعد تطبيق الصلاحيات.

معرفة الكود ومخطط قاعدة البيانات مقصورة على حسابات `ADMIN` و`SUPER_ADMIN`، بينما
تبقى معرفة كل مستخدم بالبيانات الحية مقيدة بصلاحياته والتسلسل الإداري. يعرض عارف
مصادر الإجابة وأرقام الأسطر عند الاستناد إلى ملفات المشروع. يعاد بناء الفهرس تلقائيًا
كل خمس دقائق، ويمكن للإدارة إجباره على التحديث عبر:

```text
GET  /api/assistant/knowledge/status
POST /api/assistant/knowledge/reindex
```

يمكن تفعيل إجابات نموذج ذكاء اصطناعي خارجي اختياريًا عبر متغيرات البيئة التالية:

```text
ASSISTANT_AI_ENABLED=1
OPENAI_API_KEY=...
OPENAI_CHAT_MODEL=gpt-5.6-luna
ASSISTANT_AI_CONTEXT_CHARS=16000
ASSISTANT_AI_MAX_OUTPUT_TOKENS=1100
ASSISTANT_PROJECT_KNOWLEDGE_ENABLED=1
ASSISTANT_INDEX_REFRESH_SECONDS=300
```

يجب ضبط هذه القيم كمتغيرات بيئة على الخادم ثم إعادة تشغيل التطبيق. لا تضع مفتاح
OpenAI داخل الكود أو README ولا ترسله في محادثة عارف. إذا كان النموذج غير مفعّل
تظهر الواجهة بوضوح أنها في «محادثة محلية»؛ وعند نجاح الاتصال تظهر «محادثة ذكية».
وللتشغيل المحلي يمكن نسخ `.env.example` إلى `.env`، ثم وضع المفتاح الحقيقي في
`.env` فقط؛ يحمّل التطبيق هذا الملف تلقائيًا، وهو مستثنى أصلًا من Git.

إذا لم تكتمل هذه الإعدادات أو تعذر الاتصال بالخدمة الخارجية، يعود المساعد
تلقائيًا إلى الوضع المحلي. عند تفعيل النموذج الخارجي لا يرسل عارف المشروع كاملًا؛
يرسل فقط المقاطع ذات الصلة التي استرجعها محليًا للسؤال الحالي. ملفات البيئة، قواعد
البيانات، النسخ الاحتياطية، المرفقات، ومجلدات التشغيل مستثناة من فهرس الملفات.

## تحديثات (Highlights)

### 1) شعبة (Division) بعد الأقسام
- تمت إضافة كيان **Division** في الهيكل التنظيمي.
- **الشعبة اختيارية** ويمكن أن تتبع:
  - **قسم (Section)** أو
  - **دائرة (Department)**
- تم ربطها مع صفحات **Master Data** والصلاحيات والواجهات بنفس نمط المنظمات/الإدارات/الدوائر/الأقسام.

### 2) تحسينات العلاقات في الهيكل التنظيمي
- دعم إسناد **القسم (Section)** إلى **إدارة (Directorate)** أو **دائرة (Department)** (اختياريًا).

### 3) Timeclock Auto‑Sync (قراءة ملف الدوام تلقائيًا)
- بدل تحميل ملف الدوام يدويًا، يمكن للنظام قراءة الملف مباشرة من **مسار ثابت على السيرفر**.
- يتم تشغيل مهمة مزامنة تلقائية (Scheduler) وتحديث بيانات الحضور.
- **ملاحظة Flask 3:** تم استبدال `before_first_request` (الذي أزيل في Flask 3) بمنطق تشغيل مرّة واحدة على أول Request.

> الإعدادات المهمة في `config.py` أو Environment:
- `TIME_CLOCK_FILE` : مسار ملف الدوام على السيرفر
- `TIME_CLOCK_SYNC_ENABLED` : تفعيل/تعطيل المزامنة
- `TIME_CLOCK_SYNC_INTERVAL_SECONDS` : فترة التحديث

### 4) تحسينات UX عامة للبوابة
- **ترتيب (Sorting) Server‑Side** لكل جداول البوابة عبر الضغط على عنوان العمود.
- **بحث عام** يدعم البحث في **كل الأعمدة** (وليس عمود الاسم فقط).
- **قوائم منسدلة قابلة للبحث** (Searchable Dropdowns) في مسار + البوابة لتسهيل اختيار الدوائر/الأقسام… إلخ.

### 5) CTA موحد في الشريط الجانبي
- توحيد مظهر اختصارات **طلب جديد** و **رفع ملف** بنفس اللون (Primary) مع تصميم مميز (`nav-cta`) و Responsive.
